# 검토 라운드 기록

"검토 10회"는 **서로 다른 관점의 검사 라운드**를 각각 돌리고, 나온 결함을 고친 뒤 회귀 테스트로 남긴 기록입니다. 아래 14개 라운드 모두 최소 1개 이상 결함을 찾았거나(★), 문제 없음을 확인했습니다(○). 자동 테스트는 현재 **183개**(야구 66 + 축구 117)입니다.

| # | 라운드 | 방법 | 결과 |
|---|---|---|---|
| 1 | 경기 보정 | 3,000~6,000경기 측정 | ★ 4건 |
| 2 | 결정성/난수 | 몰아서 vs 조금씩 비교, 직렬화 후 재개 | ★ 1건(야구에서 발견) → 축구에 회귀 테스트 |
| 3 | 저장/복원 | 왕복 deep-equal, 손상/변조/오타입 | ★ 2건 |
| 4 | 경제/재정 | 구단별 시즌 손익, 방치 5시즌 | ★ 2건 |
| 5 | 악용(자금 복사) 탐색 | 규칙을 읽으며 순환 거래 찾기 | ★ 3건 |
| 6 | 규칙 정확도 감사 | 출처 대조 + 테스트 | ★ 1건, 미확인 5건 명시 |
| 7 | 선수 모델 현실성 | 분포 측정 | ★ 2건 |

## 1. 경기 보정
- ★ **득점이 리그 수준에 따라 변함**: 같은 규칙인데 능력 절대값이 높은 EPL은 팀당 2.1골, K리그는 1.9골 → 경기 안 두 팀의 평균 공격/GK 수준으로 정규화. 테스트 "득점 수준은 팀 능력 절대값과 무관".
- ★ **잔여 편향**: 낮은 수준 3.38골 vs 높은 수준 2.91골 → `kA^-0.25` 보정, 이후 리그별 득점 보정 재측정(EPL 0.69, BL 0.77, KL 0.65).
- ★ **홈 이점이 사실상 0**: 1.022 → 1.10으로. 처음 측정은 "A팀만 홈"이라 팀 실력 차이에 오염되어 있었음(테스트 설계 오류) → **홈/원정 번갈아 측정**하도록 테스트를 고침.
- ★ **교체가 거의 안 일어남**: 측정해 보니 팀당 평균 **0.19명**이었음(처음 테스트는 임계값이 느슨해서 통과했음). 가장 지친 한 명만 보던 로직을 "가장 이득이 큰 (경기장 선수, 벤치 선수) 쌍" 선택으로 바꿔 **평균 3.0명**(상한)으로. 테스트 기준을 2~3명으로 엄격하게.
- ○ 유효슈팅 비율 40% → 30%(현실 범위로).

## 2. 결정성/난수
- ★ (야구에서 발견) `finishSeason`이 난수 상태를 중첩해서 만들어 **몰아서 처리한 결과와 조금씩 처리한 결과가 달랐음** → 난수를 인자로 넘김. 축구는 설계부터 `withRng` 한 번만 쓰고, 테스트 "오프라인 몰아서 진행 = 조금씩 진행", "직렬화 후 이어서 진행해도 같은 결과"가 지킴.

## 3. 저장/복원
- ★ **방출/만료 선수가 사라짐**: 오프시즌 시작 직후 시장 갱신이 자유계약 명단을 지움 → `keep` 표시.
- ★ 압축 복원 후 `suspend: 0` 같은 기본값 차이로 deep-equal 실패 → 구조만 접고 값은 보존.
- ○ 체크섬 변조, 다른 게임 세이브, 빈/이상한 입력, 용량 초과, 접근 거부 → 모두 안전.

## 4. 경제/재정
- ★ **강팀은 적자·약팀은 흑자**(수입이 선형, 연봉이 지수) → 수입도 평판 지수로, 부별 기준값 역산(임금/수입 0.78).
- ★ **방치하면 파산**(분데스 −129억): 자동 재계약이 시장 연봉으로 계속 올려줌 → 재정 한도(+5%p)를 넘으면 포기.
- ○ 방치 5시즌 테스트(3리그)에서 파산하지 않음.

## 5. 악용 탐색 (규칙을 읽으며 순환 찾기)
- ★ **임대 무한 자금**: 임대 보내기→복귀→재임대로 임대료(가치 4%)를 반복 수령 → 복귀 시 임대료 반환.
- ★ **자유계약 시세 차익**: 계약 보너스 0.24억으로 데려와 즉시 매각 4.6억 → (1) 자유계약 시장에는 "남는 선수"만, (2) 영입 후 19라운드 매각 불가, (3) 자유계약 선수는 가치 25%만 인정.
- ★ **이적 등록 차익**: 영입가 1.2배 vs 제안 최대 1.47배 → 호가 상한 1.15배, 제안은 호가 이하.
- 회귀 테스트 4개.

## 6. 규칙 정확도 감사
- 일정 테스트가 공식 값과 대조: EPL 38/19, 챔피언십 46, 분데스 34(306경기), K2 32경기(272경기), K1 33라운드(198경기).
- ★ **K2는 17팀(홀수)** → 일정 생성기에 부전 처리 추가.
- ★/○ **미확인(게임 설정으로 표시)**: EPL 강등 3팀(표준이나 문장 미확인), K리그 이적 기간, 독일·한국 임대 한도, 챔피언십·2. 분데스 전체 구단, K리그 2026 임시 승강 방식(김천 특례는 일반 방식으로 단순화).

## 7. 선수 모델 현실성
- ★ **17세 CA 131**(나이와 능력이 독립) → 나이 보정.
- ★ **골키퍼가 필드 능력치가 높아 ST로 98** / 스트라이커의 수비 능력이 높음 → 포지션 밖 능력치를 낮게 생성.

## 8. UI/UX · iOS (아이폰 크기 Chromium, 밝은/어두운 테마)
- ★ 전술 피치에서 **골키퍼가 잘림**(y=100).
- ★ 소식의 **금액 단위 오류**(4,294,600만) → 억 단위 변환.
- ★ 중계 중 **결과 스포일러**(순위·승점) → 가림.
- ★ **textarea 글자 11px** → iOS가 입력 때 화면 확대 → 16px.
- ★ 따라잡기 2.6초 동안 멈춘 듯 보임 → "계산 중" 화면.
- ★ 0경기 건너뛰기 시 아무 반응 없음 → 안내 토스트.
- (스크린샷의 시트 비침은 애니메이션 도중 캡처라 결함이 아님 → 점검 스크립트가 애니메이션이 끝난 뒤 캡처.)

## 9. 접근성 (WCAG AA 4.5:1)
- ★ 라이트 보조 글자색 4.12, 앰버 3.50(작은 글씨), 점토색 4.36 → 5:1 이상으로 조정(`#6a664f`, `#85600f`, `#a64a27`). 다크는 이미 통과.
- ★ 흰 글씨 위 앰버 배지 4.06 → 5.7.
- ○ 본문 14.7:1, 전광판 6.5:1.

## 10. 오프라인/PWA
- ○ 테스트가 확인: 서비스 워커 캐시 목록에 앱 파일이 빠짐없이 있고 없는 파일이 없음, 캐시 이름이 게임별로 다름, 매니페스트 아이콘 존재, iOS 메타(`apple-mobile-web-app-capable`, `viewport-fit=cover`), **외부 URL/CDN/폰트 없음**. Chromium에서 서비스 워커 등록 후 **네트워크를 끊고 재로드**해 열림 확인.
- 미검증: iOS 실기기(저장 7일 규칙, 설치 앱 저장소 분리).

## 11. 정적 분석 (ESLint, 오류 0)
- ★ 미사용 import/변수 7건, 빈 catch 블록 3건 → 정리.

## 12. 보안
- ○ 이름/구단명 XSS가 이스케이프됨(홈, 선수단, 구단 선택 화면 테스트), `__proto__` 오염 시도 무해, 숫자 아닌 값·음수 나이·200자 이름은 거절/대체, 6MB 초과 거절, 외부 통신 없음.

## 13. 성능
- 경기 0.5ms, EPL 라운드(1·2부) 22ms, 3리그 120라운드 따라잡기 1.4~2.6초.
- ★ 저장 크기: 10시즌 +30KB → 오래된 시즌 상세 표 정리(최근 3시즌만).
- ★ 따라잡기 중 멈춤 → "계산 중" 화면(8라운드 이상 밀렸을 때).

## 14. 문서 감사
- ★ 승률 범위를 뭉뚱그림 → 실측값(+10/+20/+30 CA → 51/65/77%)으로.
- ★ 이적 기간 표현을 EPL/분데스 5라운드, K리그 6라운드로 정정.

## 남은 위험 (정직하게)
1. **아이폰 실기기 미검증.** 점검표로 직접 확인해야 합니다.
2. iOS의 7일 저장소 삭제 규칙이 홈 화면 앱에 적용되는지 **불확실** → 백업 알림으로 완화.
3. 공식 값을 확인 못 한 규칙(위 6절)이 있습니다.
4. 경기 엔진은 "현실적인 통계"를 목표로 보정했지 실제 선수 단위 재현이 아닙니다(예: 특정 전술의 세밀한 효과는 단순화).
5. 장기(수십 시즌) 리그 수준 변화는 3시즌/8시즌 시뮬레이션으로만 확인했습니다(±14 CA 이내).
