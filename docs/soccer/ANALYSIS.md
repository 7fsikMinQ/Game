# 분석 10개 관점

"분석 10회"는 같은 분석을 10번 반복한 것이 아니라 **서로 다른 10개 관점**에서 한 번씩 근거를 모으고 결정한 기록입니다. 각 관점에서 실제로 실험하거나 검색한 것과, 그 결과 설계에 반영한 것을 적었습니다.

| # | 관점 | 질문 |
|---|---|---|
| 1 | FM이 무엇을 하는 게임인가 | 어떤 요소가 FM답고, 무엇을 버려도 되는가 |
| 2 | 폰 · 방치형에 맞는가 | FM을 폰으로 옮기면 무엇이 안 맞는가 |
| 3 | iOS의 기술 제약 | 닫아둔 동안 어떻게 "진행"시키는가, 저장은 안전한가 |
| 4 | 선수 데이터 모델 | CA/PA 1~200, 능력치 1~20을 어떻게 만들고 유지하는가 |
| 5 | 경기 엔진 | 현실적이면서 0.5ms인 경기를 어떻게 만드는가 |
| 6 | 2026년 리그 규칙 | EPL/분데스/K리그의 경기 수·승점·승강·이적 규칙 |
| 7 | 돈: 재정·이적·임대 | 강팀/약팀 모두 균형이 맞고 악용되지 않는가 |
| 8 | AI | 어시스턴트와 상대 AI를 어떻게 값싸게, 효과적으로 |
| 9 | 데이터와 법 | 실제 이름·나이·유망주 이슈를 어디까지 넣을 수 있는가 |
| 10 | UX · 오프라인 · 저장 | 폰에서 쉽고, 인터넷 없이 되고, 안 날아가는가 |

---

## 1. FM이 무엇을 하는 게임인가
- **조사**: FM23(스쿼드 플래너, Recruitment Focus, 데이터 허브), FM24(선수 목표, 중개인 매각, 세트피스 코치), FM26(국면별 포메이션, TransferRoom 이적, Touch 판). FM25는 취소.
- **결론**: FM의 정체성은 ① **숫자 체계**(CA/PA 1~200, 능력치 1~20, 포지션 숙련도) ② **선수단 관리 루프**(라인업·전술·훈련·이적·계약·재정) ③ **장기 성장**(유스, 노화). 3D 중계, 협상 대화, 코치 수십 명은 정체성이 아니라 **분량**.
- **반영**: ①②③은 유지, 분량은 어시스턴트로 흡수([FM-COMPARISON.md](FM-COMPARISON.md)).

## 2. 폰 · 방치형에 맞는가
- **조사**: FM26 Touch가 "빠른 세션, 핵심 루프, 화면당 타일 수 축소"로 모바일화한 방식.
- **결론**: 폰에서는 *하루 몇 번, 30초씩* 열어도 되어야 합니다. 그러려면 (a) 홈에서 다음 경기·예상·**계속 버튼** 한 화면, (b) 선택은 "확인만" 하면 되도록 기본값이 좋아야 함.
- **반영**: 하단 탭 5개, 홈의 `계속 ▶ / 5라운드 / 시즌 끝까지`, 어시스턴트 기본 켜짐, 방치형 자동 진행, "자리를 비운 동안" 요약.

## 3. iOS의 기술 제약
- **조사**: 서비스 워커는 HTTPS만, iOS 26에서 홈 화면에 추가한 사이트는 기본 웹앱, Safari 7일 저장소 삭제 규칙(홈 화면 앱 면제 여부 미확인), Safari 탭과 설치 앱의 저장소 분리 보고.
- **실험**: 경기 하나를 "열 때 따라잡기"로 처리하면 결과가 한 번에/조금씩이 같은지 → 자동 테스트로 **결정성** 확인.
- **결론**: 백그라운드 진행은 불가 → 시각 저장 + 따라잡기(최대 120라운드, 이후 타이머 재설정). 저장은 **믿지 말고 백업을 유도**.
- **반영**: `nextGameAt` 모델, `persist()` 요청, 7일마다 백업 알림, 파일/복사 백업, 계산 중 안내(2.6초).

## 4. 선수 데이터 모델
- **실험**: 포지션별 가중으로 CA를 계산하고, 목표 CA ±1에 맞춰 생성 → 오차 ≤ 4(테스트). 유스가 PA를 넘겨 크지 않는지, 어린 선수가 빨리 크는지, 31세부터 떨어지는지.
- **발견**: 나이와 CA가 독립이면 **17세 CA 131**(EPL 평균급)이 생김 → 나이 보정(17세 −33) 도입.
- **발견**: 유망주 PA는 단일 분포가 아니라 **등급(이슈)별 분포**여야 "이슈가 큰 선수일수록 PA가 높다"를 표현 가능 → hype 0~4 도입, 18세 중 PA 160↑ 1.8%, 180↑ 0.3%(근거: FM 가이드의 PA 160/180 의미 + 아카데미 4% 연구).
- **반영**: [DESIGN.md 3절](DESIGN.md).

## 5. 경기 엔진
- **설계 선택지**: (a) 타석처럼 결과만 굴리기 (b) 분 단위 점유/찬스 (c) 선수 위치 시뮬레이션. (c)는 폰에서 느리고 오프라인 따라잡기가 불가 → **(b)**.
- **실험**: 경기당 0.5ms, 리그 라운드 22ms. 득점이 리그 수준(능력 절대값)에 따라 달라지는 편향 발견 → 경기 안 두 팀 평균으로 **정규화**, 낮은 수준 리그에서 남는 편향은 `kA^-0.25`로 보정. 홈 이점은 홈/원정을 번갈아 측정해 1.10으로 보정(기존 1.03은 사실상 0이었음).
- **결과**: 득점 EPL 1.47 / BL 1.64 / KL 1.35(팀당), 홈 45·무 23·원정 32%, 팀당 교체 3명.

## 6. 2026년 리그 규칙
- **조사**: [RESEARCH.md 2절](RESEARCH.md)(약 20건). 일정(38/46/34/33+5/32), 강등·플레이오프, 임대 한도 2명(EPL 공식), 이적시장 날짜, 재정 규정(EPL SCR 85%, 분데스 70%).
- **한계**: 2. 분데스·챔피언십 전체 구단 목록, K리그 이적/임대 규정은 확인하지 못함 → 게임 설정으로 표시.
- **반영**: `LEAGUES` 설정 + 테스트가 경기 수/홈 경기 수를 공식 값과 대조.

## 7. 돈: 재정·이적·임대
- **실험**: 처음에는 강팀은 적자·약팀은 흑자 → 수입도 평판에 지수 비례로(구단 평균 임금/수입 0.78). 자동 재계약이 분데스에서 −129억까지 파산 → 재정 한도를 넘으면 재계약 포기.
- **발견(악용)**: 임대 반복 수령, 자유계약→즉시 매각, 이적 등록 차익 → 규칙 4개로 봉쇄(영입 후 19라운드 매각 불가, 임대료 반환, 호가 상한, 자유계약 가치 25%).
- **결과**: 방치 5시즌(3리그)에서 파산하지 않음, 구단별 시즌 손익이 대부분 ±.
- **반영**: [DESIGN.md 6~7절](DESIGN.md).

## 8. AI (어시스턴트와 상대)
- **질문**: "AI 기능을 최대 효율로"의 현실적 의미 = ① 게임 안의 AI가 똑똑하게 ② 값싸게 돌아야(0.5ms) ③ 오프라인.
- **결정**: LLM은 서버/키가 필요해서 **제외**. 대신 규칙 기반 어시스턴트: 라인업(피로 반영 = 자동 로테이션), 포메이션 평가, 경기 **예상 승률(푸아송, 시뮬레이션 없이 <1ms)**, 자동 재계약(재정 한도), 유스 선택. 상대 AI는 같은 어시스턴트를 쓰고 포메이션 재평가는 6라운드마다(비용 절감).
- **검증**: 추천 포메이션 점수, 예상 승률이 선수 능력 상승 시 오르는지 테스트.

## 9. 데이터와 법
- **조사**: 맨유 vs FM, Keller/Hart 판례, Transfermarkt 약관(스크래핑 금지), football-data.org 범위(불분명), openfootball(명단 없음), Wikipedia CC BY-SA, 이 환경은 페이지 접근 불가.
- **결론**: (1) 개인 기기에서 실제 이름을 쓰는 것은 위험이 낮지만 (2) 공개 저장소에 올리는 순간 배포이고 (3) 정확한 명단을 확보할 수 없음 → **앱에는 실제 데이터 없음, 사용자가 가져오는 팩**.
- **반영**: `pack.js`(CSV/JSON 검증·적용·환산), 검증된 구단명 템플릿, [REAL-DATA.md](REAL-DATA.md).

## 10. UX · 오프라인 · 저장
- **점검**: 아이폰 크기 브라우저(393×852)에서 전 화면 확인 → 피치의 GK 잘림, 소식 금액 단위 오류, 중계 중 결과 스포일러, textarea 16px 미만(iOS 확대), 대비(WCAG AA) 미달 발견·수정.
- **오프라인**: 서비스 워커 캐시 목록이 실제 파일과 일치하는지 테스트가 확인, 외부 URL 금지 테스트.
- **저장**: 두 칸 교대 + 체크섬 + 압축, 깨진 칸 복구, 다른 게임 세이브 거부, 용량 초과/접근 거부에도 앱이 죽지 않음.
