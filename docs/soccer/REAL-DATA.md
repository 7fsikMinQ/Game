# 실제 구단·선수 데이터 (개인용으로 가져오기)

## 질문: "나 혼자 쓰는 건데 실제 이름 그대로 써도 되지 않나?"

**본인 기기에서만 쓰는 개인 용도라면 사실상 문제될 가능성은 낮습니다**(법률 자문은 아닙니다). 위험이 생기는 지점은 **공개 저장소·공개 URL에 실제 선수 이름·얼굴을 올려서 배포하는 것**입니다. 조사에서 확인한 것([RESEARCH.md 5절](RESEARCH.md)):

- 맨유가 FM을 상표권으로 소송했고 FM이 "Man UFC"로 바꿨습니다.
- 이름을 바꿔도 실제 선수와 거의 같은 아바타는 초상권 소송이 진행됐습니다(미국 판례).
- 실제 이름 모드는 흔하지만 **배포·수익화**가 문제가 됩니다.

이 저장소(`7fsikMinQ/Game`)는 **공개(public)** 이고 GitHub Pages로 배포되기 때문에, 실제 선수 이름을 저장소에 넣으면 "개인용"이 아니라 "공개 배포"가 됩니다. 그래서:

1. **앱/저장소에는 실제 선수 데이터를 넣지 않았습니다.**
2. 대신 **내 데이터 팩 가져오기**를 만들었습니다. 가져온 데이터는 **이 기기의 저장소에만** 들어가고 서버·저장소로 가지 않습니다.
3. 이 방식이면 "실제 이름으로 플레이"는 **본인 폰에서만** 됩니다.

제가 직접 실제 명단을 만들어 드리지 못하는 이유는 법이 아니라 **데이터 확보 문제**입니다:
- 이 개발 환경에서는 Wikipedia 등 페이지를 직접 열 수 없고(8번 시도 모두 실패) 검색 요약만 볼 수 있습니다.
- 2026/27 명단(약 2,600명)과 나이는 이적시장마다 바뀌고, 기억으로 채우면 **틀린 정보를 사실처럼 넣게 됩니다**.
- Transfermarkt는 자동 수집을 약관으로 금지한다고 알려져 있고, football-data.org의 선수단 제공 범위는 확인하지 못했습니다.

**제안**: 원하는 구단의 선수 명단을 (본인이 보는 사이트에서) 복사해서 이 대화에 붙여넣어 주시면, 아래 CSV 양식으로 **변환/검증**해 드립니다(정확성은 붙여넣은 출처에 달려 있습니다).

## 가져올 수 있는 것

| 단계 | 넣는 것 | 결과 |
|---|---|---|
| 1. 구단명만 | `docs/data/clubs-*.csv` 그대로 가져오기 | 실제 구단 이름 + 지난 시즌 순위에 맞는 전력(선수는 가상) |
| 2. 일부 선수 | 몇 명만 입력 | 실제 선수는 그대로, 나머지 자리는 가상 선수로 채움 |
| 3. 전체 명단 | 구단당 20~30명 | 완전한 실제 팀 |

### 구단명 템플릿 (검증된 것만)

`docs/data/` 에 있습니다. 공개 정보(공식 구단명)만 담았고 로고·유니폼·선수는 없습니다.

| 파일 | 내용 | 상태 |
|---|---|---|
| `clubs-epl-2026-27.csv` | EPL 20팀(공개된 2026/27 목록) | 순위가 확인된 팀만 순위 기재 |
| `clubs-bl-2026-27.csv` | 분데스리가 18팀 | 순위 일부 비어 있음 |
| `clubs-kl-2026.csv` | K리그1 12팀(순위 포함) + K리그2 17팀 | 2부는 일부 순위만 |

순위가 빈 구단은 **중간 순위**로 취급하고, 팀 수가 모자라는 부는 **가상 구단으로 채웁니다**(가져오기 화면에 "참고"로 표시). 마지막 열 `note`는 무시됩니다.

## CSV 형식

한 줄 = 선수 한 명(또는 구단만 있는 줄). 쉼표 또는 탭 구분, UTF-8. 첫 줄은 열 이름.

| 열 | 뜻 | 예 |
|---|---|---|
| `country` | `epl` / `bl` / `kl` (또는 잉글랜드/독일/한국) | `epl` |
| `division` | 1 또는 2 | `1` |
| `club` | 구단 이름(24자까지) | `샘플 FC` |
| `rank` | (선택) 지난 시즌 순위 → 전력 순서 | `1` |
| `rep` | (선택) 평판 직접 지정(리그별 범위 밖이면 보정) | `70` |
| `name` | 선수 이름(24자까지). 비우면 구단만 있는 줄 | `김샘플` |
| `pos` | GK, CB/DF, LB, RB, DM, CM/MF, LW, RW, AM, ST/FW 등 | `ST` |
| `birth` | 생년월일 `YYYY-MM-DD` → **실제 나이**(기준일 2026-10-08) | `2001-04-12` |
| `age` | birth가 없을 때 나이 | `25` |
| `ovr` | (선택) 종합능력 1~99(게임 OVR 같은 값) | `84` |
| `ca` | (선택) 현재능력 1~200. 있으면 ovr/value보다 우선 | `140` |
| `value` | (선택) 시장가치, **백만 단위**(€45m이면 `45`) | `45` |
| `hype` | (선택) 유망주 등급 0~4 | `3` |
| `pa` | (선택) 잠재능력 1~200. 있으면 hype보다 우선 | `160` |
| `contract_end` | (선택) 계약 만료 연도 | `2029` |

양식 예: [`docs/data/sample-pack.csv`](../data/sample-pack.csv) (가상 선수). 가져오기 화면의 **CSV 양식 복사** 버튼도 같은 내용입니다.

## 능력은 어떻게 정해지나 (우선순위)

선수 한 명의 CA(현재능력):
1. `ca`가 있으면 그대로.
2. 없으면 `ovr`(1~99) → `CA = 2.9×(ovr−45)+50` (예: 65→108, 75→137, 85→166).
3. 없으면 `value`(백만) → `CA = 62 + 20×ln(value+1)` (예: 1→76, 10→110, 50→140, 100→153, 200→168).
4. 모두 없으면 그 구단의 평균 수준 ±11로 무작위.

> 위 환산식은 **직접 만든 근사치**입니다. EA 종합능력/시장가치 → FM CA의 공식 환산표는 찾지 못했습니다([RESEARCH.md](RESEARCH.md)). 능력이 마음에 안 들면 `ca`를 직접 적으세요.

세부 능력치 24개는 CA와 포지션에 맞춰 **자동 생성**됩니다(실제 선수별 세부 능력치는 가져오지 않음). 그래서 같은 CA의 같은 포지션 선수는 "스타일"만 다르게 생성됩니다.

## 유망주 이슈 → 잠재력(PA)

PA는 이렇게 정해집니다:
1. `pa`가 있으면 그대로.
2. 없고 `hype`(0~4)가 있으면 그 등급의 범위에서 뽑음: 0=평범, 1=95~135, 2=120~155, 3=145~176, 4=168~197(항상 CA 이상).
3. 둘 다 없고 **23세 이하이면서 `value`와 `ovr/ca`가 있으면** "시장가치가 능력으로 설명되는 값보다 얼마나 높은가"로 등급을 자동 추정합니다. (현재 능력 대비 가치 배율이 1.5배↑=1, 2.5배↑=2, 4배↑=3, 8배↑=4). 어린 선수에 붙는 **잠재력 프리미엄 = 시장·언론의 기대(이슈)** 라는 해석입니다.
4. 그 외에는 나이에 따른 기본 규칙(26세 이상은 PA≈CA).

즉 **"이슈가 큰 유망주일수록 PA가 높다"** 는 `hype` 또는 `value`로 반영됩니다. 같은 등급이어도 범위 안에서 무작위이고, 게임 중 19~22세에 대기만성/기대 이하가 일어납니다(실제로 유망주가 모두 성공하지 않는 것을 반영: [RESEARCH.md 4절](RESEARCH.md)).

## 가져오는 방법 (아이폰)

1. 위 형식으로 CSV를 만듭니다(메모 앱/스프레드시트에서 CSV로 내보내기). 선택: PC에서 `node tools/make-pack.mjs 내데이터.csv` 로 미리 검사.
2. 앱을 열고 **새 게임 → 리그 선택 화면의 "내 데이터 가져오기" → 가져오기**.
3. CSV를 **붙여넣거나 파일 선택** → **검사하기**. 오류가 있으면 이유가 나옵니다. 통과하면 **이 데이터로 구단 고르기**.
4. 이후는 일반 새 게임과 같습니다. 이름은 세이브에 들어가므로 백업 파일에도 포함됩니다(백업 파일을 공유할 때 주의).

데이터 팩은 새 게임을 시작할 때만 적용됩니다(진행 중인 세이브에는 적용되지 않음).

## 시즌이 지나면?

가져온 선수도 게임 규칙대로 나이를 먹고, 성장·노화·은퇴하며, AI 구단은 유스·보충으로 선수를 채웁니다. 즉 **2026/27 시작 시점의 실제 명단**이 출발점이고 이후는 가상 미래입니다.

## 개인정보/안전

- 데이터는 `localStorage`(이 기기·이 도메인)에만 저장됩니다. 서버로 보내지 않습니다.
- 가져오기는 크기(6MB), 형식, 숫자 범위, 이름 길이를 검사하고, 화면에 나올 때 HTML 이스케이프됩니다(악성 이름 테스트 포함).
- **GitHub에 실제 데이터 파일을 커밋하지 마세요.** 개인 데이터는 `private/` 폴더에 두면 `.gitignore`가 막아 줍니다.

## 데이터를 어디서 구하나 (제안, 약관은 직접 확인)

- 구단·순위: 리그 공식 사이트, 방송사/포털 순위표(직접 보면서 적기).
- 선수 명단·나이: 구단 공식 사이트, Wikipedia의 시즌 문서(CC BY-SA, 개인 사용은 자유롭고 재배포 시 출처 표기).
- Transfermarkt는 자동 수집을 약관으로 막고 있다는 보도가 있으니 **스크래핑하지 마세요**. 직접 보고 적는 것은 개인 용도로 가능합니다.
- 유료/공식 API(예: football-data.org 유료 플랜 등)는 약관과 제공 범위를 먼저 확인하세요.
