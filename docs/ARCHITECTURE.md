# 구조와 설계

## 한눈에

```
브라우저(아이폰 Safari / 홈 화면 웹앱)
 └ index.html ─ css/app.css
    └ src/app.js            DOM 연결, 1초 타이머, 이벤트, 저장 호출
       ├ views.js           상태 → HTML 문자열 (순수 함수)
       ├ game.js            상태와 규칙: 시즌·진행·경제·오프시즌·개발자 메뉴
       │  ├ sim.js          한 경기 시뮬레이션 (타석 단위)
       │  ├ league.js       선수/팀 생성, 일정, 타순
       │  └ rng.js          시드 난수 (상태 저장 가능)
       └ storage.js         두 칸 교대 저장 + 체크섬 + 백업
 sw.js                      서비스 워커 (오프라인)
```

원칙:
- `game.js`/`sim.js`/`league.js`/`rng.js`/`storage.js`/`views.js` 는 **브라우저 API를 쓰지 않습니다.** 그래서 Node에서 그대로 테스트됩니다. DOM을 만지는 코드는 `app.js` 한 파일뿐입니다.
- 상태(`state`)는 **JSON으로 직렬화 가능한 평범한 객체** 하나입니다. 저장·백업·복원·테스트가 전부 이 성질에 기대고 있습니다.
- 의존성과 빌드 단계가 없습니다. ES 모듈을 브라우저가 그대로 읽습니다.

## 방치형 시간 모델

iOS는 화면이 꺼지거나 앱이 백그라운드로 가면 웹앱의 JavaScript를 멈춥니다. 백그라운드 동기화도 웹앱에는 사실상 없습니다.
그래서 "계속 돌리기" 대신 **"다음 경기 시각"을 저장하고, 열 때 따라잡기** 방식을 씁니다.

```
state.nextGameAt = 다음 경기가 열릴 시각(ms)
advance(state, now):
   due = floor((now - nextGameAt) / 간격) + 1        // 밀린 경기 수
   run = min(due, 200)                                 // 상한
   run번 tickOnce()                                    // 라운드 1개씩 진행
   nextGameAt += run * 간격   (상한을 넘겼으면 now + 간격 으로 재설정)
```

- **결정적**: 같은 시드/상태면, 한 번에 600분을 처리해도 1분씩 600번 처리해도 결과가 같습니다. (`season.test.mjs`가 검증. 난수를 `withRng`로 한 번만 감싸서 보장)
- **상한 200경기**: 몇 주 만에 열어도 한 번에 무한정 계산하지 않습니다. 넘으면 타이머를 지금부터 다시 시작합니다.
- **시계 역행 방어**: `nextGameAt`이 `now`보다 간격 이상 미래면 `now + 간격`으로 맞춥니다. (기기 날짜를 되돌려 악용하거나, 실수로 바꿔도 안 멈춤)
- **오프시즌은 정지**: 시즌 사이에는 시간이 안 흐르고, 사용자가 "다음 시즌 시작"을 눌러야 합니다. (드래프트라는 선택지를 주기 위한 의도적 정지)
- 한 틱 = 라운드 1개. 8팀이라 라운드마다 4경기가 열리고, 내 경기만 로그를 남기며(`log:true`) 나머지는 결과만 기록합니다.
- 앱이 열려 있고 경기가 막 끝났을 때만 **중계 연출**(플레이를 0.42초 간격으로 공개)을 합니다. 닫아둔 동안 쌓인 경기는 "자리를 비운 동안" 요약 카드로 보여줍니다.

## 시즌 구조

- 8팀, 정규시즌 42경기(= 7라운드 × 6사이클. 같은 상대와 6번, 홈/원정은 사이클마다 교대 → 홈 21경기).
- 상위 4팀 포스트시즌 단판 토너먼트: 1위-4위, 2위-3위 → 결승. 내 팀이 없는 라운드는 같은 틱에 즉시 끝냅니다.
- 오프시즌: 시즌 보상 → 신인 드래프트 → 다음 시즌 (나이 +1, 성장/노화, 38세 은퇴 후 신인 보충, AI 팀은 가장 약한 선수를 신인으로 교체).

## 경기 시뮬레이션 (`sim.js`)

타석마다 한 번의 난수로 결과를 정합니다. `b` = 타자, `p` = 투수.

| 결과 | 확률 (범위 제한) |
|---|---|
| 삼진 K | `0.205 + (구위-50)*0.0042 - (컨택-50)*0.0030` (0.07~0.40) |
| 볼넷 BB | `0.085 + (선구-50)*0.0018 - (제구-50)*0.0020` (0.025~0.18) |
| 홈런 HR | `0.028 + (파워-50)*0.0007 - (구위-50)*0.0002 - (제구-50)*0.0001` (0.004~0.085) |
| 인플레이 안타 | `0.300 + (컨택-50)*0.0022 + (파워-50)*0.0006 + (주력-50)*0.0004 - (구위-50)*0.0008 - (팀수비평균-50)*0.0016` (0.20~0.40) |
| 안타 종류 | 3루타 `0.03+(주력-50)*0.0008`, 2루타 `0.21+(파워-50)*0.002`, 나머지 단타 |
| 아웃 | 땅볼 48% / 뜬공 52%. 땅볼+1루 주자+2아웃 미만이면 병살 42%, 뜬공+3루 주자+2아웃 미만이면 희생플라이 55% |

- 주자 진루는 주력 보정이 있는 단순 규칙(단타에 2루 주자 득점 60%+, 2루타에 1루 주자 득점 40%+ 등).
- **투수 교체**: 선발은 투구수 `55 + 체력*0.6`(체력 50→85구, 90→109구)이거나 6실점이면 교체. 구원 3명이 순서대로 등판하고 마지막 구원은 끝까지 던집니다. 투구수가 한계의 85%를 넘으면 구위·제구 -10.
- 타순(`getLineup`): 종합 능력치 순위로 1번=2위, 2번=4위, 3번=1위, 4번=3위, 5~9번=5~9위.
- 9회 이후 홈이 앞서면 말 공격 생략, 말 공격 중 역전하면 끝내기로 즉시 종료. 15회까지 비기면 동전 던지기로 한 점을 줍니다.
- 승·패 투수는 **근사치**입니다: 승리 팀 선발이 5이닝 이상이면 선발, 아니면 마지막 투수. 패전도 비슷하게 판정합니다. (정식 규정은 구현하지 않음)
- 책임 주자 규칙은 단순화했습니다: 득점은 그 시점의 투수 실점(`er`)으로 모두 계산합니다(자책 구분 없음).

**검증된 평균** (`sim.test.mjs`): 팀당 경기당 득점 ≈ 4.4, 경기당 팀 안타 ≈ 9, 평균 이닝 ≈ 9.2.
능력치 +10인 팀의 승률 ≈ 70%.

## 선수

- 타자: 컨택·파워·선구·주력·수비. 투수: 구위·제구·체력. 범위 25~99.
- 종합(OVR): 타자 `컨택*.32 + 파워*.28 + 선구*.18 + 주력*.10 + 수비*.12`, 투수 `구위*.45 + 제구*.35 + 체력*.20`.
- **잠재력(pot)**: 모든 능력치의 상한. 훈련으로 올려도 pot을 넘지 못합니다. 젊을수록 잠재력이 높게 생성됩니다.
- 구성: 타자 9(포지션 9개 고정) + 선발 5 + 구원 3 = 17명. 신인은 같은 계열의 선수를 대체하면서 그 자리(포지션/역할)를 물려받습니다.

## 경제 (단위: 만)

| 항목 | 공식 |
|---|---|
| 경기 수입 | `560 × (0.6 + 인기/100) × (1 + 0.2×구장Lv) × (홈 1 / 원정 0.35) + 승리 보너스 120 − 운영비(100 + 15×시설Lv합)` |
| 인기 | 0~100. 승 +1.5, 패 −1, 우승 시즌 말 +15. 시작 30 |
| 훈련 비용 | `능력치^2.2 / 10 × (1 − 0.06×훈련장Lv)` (50→547, 70→1,146, 90→1,992) |
| 시설 비용 | 구장 2,500 / 훈련장 2,000 / 스카우트 1,800 × `1.75^현재Lv`, 최대 Lv10 |
| 시즌 보상 | 우승 12,000 / 준우승 5,000 / 포스트시즌 진출 2,000 / 그 외 500 |

아무것도 안 하고 방치해도 시즌당 순수입은 약 12,000만(1.2억)이고, 능력치 50대 훈련 20여 회 분입니다. `economy.test.mjs`의 장기 밸런스 테스트가 "투자하는 쪽이 이기되 무적은 아니다"를 지키는지 확인합니다.

## 저장 (`storage.js`)

- 키 `bb.save.a`, `bb.save.b` 두 칸에 **번갈아** 씁니다(`seq` 증가). 쓰다 끊겨도 직전 칸은 온전합니다.
- 각 칸은 `{ f:'baseball-save', seq, savedAt, sum, data }`. `sum`은 `data`의 FNV-1a 체크섬(손상 감지용이며 보안 장치는 아님).
- 불러올 때 두 칸을 모두 검증하고 `seq`가 큰 유효한 칸을 씁니다. 둘 다 깨졌으면 새 게임.
- 저장 시점: 경기가 진행될 때, 사용자가 무언가 바꿀 때, 앱이 백그라운드로 갈 때(`visibilitychange`/`pagehide`).
- 백업 파일/텍스트는 같은 포맷이라 그대로 `importText()` 로 복원됩니다.
- `localStorage`가 막힌 환경(사생활 보호 모드 등)에서는 메모리 저장소로 대체되어 앱은 계속 동작하지만, 닫으면 사라집니다.
- 세이브 크기는 수십 KB(테스트가 400KB 미만을 보장). `localStorage` 한도(약 5MB)와 거리가 멉니다.

## 서비스 워커 (`sw.js`)

- 전략: **네트워크 우선, 실패하면 캐시.** 온라인이면 항상 최신, 오프라인이면 저장본.
- `install`에서 `FILES` 목록을 미리 저장, `activate`에서 이전 버전 캐시를 삭제, 이후 성공한 GET은 캐시에 갱신.
- 등록 조건: `https://` 또는 `localhost`. LAN의 `http://192.168.x.x` 에서는 등록하지 않습니다(iOS가 허용 안 함).

## 화면 (`views.js`, `css/app.css`)

- 탭 4개: 경기 / 선수단 / 순위 / 구단. 선수 상세·백업·개발자 메뉴는 하단 시트.
- `app.js`는 클릭을 `data-act` 속성으로 위임 처리합니다. 사용자가 입력하는 문자열(팀/선수 이름)은 전부 `esc()`를 거쳐 출력합니다.
- 디자인 규칙: 종이색 배경 + 잉크색 글자 + 잔디색(전광판·강조) + 점토색(득점 표시). 그라데이션·그림자·이모지 없음. 숫자는 고정폭 숫자 서체. 시스템 서체(애플 SD 고딕)만 사용해서 로딩 지연이 없습니다.
- 어두운 모드는 `prefers-color-scheme` 로 자동 전환. 아이폰 노치/홈 바는 `env(safe-area-inset-*)` 로 처리.
