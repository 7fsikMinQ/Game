# 아이폰에서 실행하기 (처음부터 끝까지)

**Mac, 개발자 계정, USB 연결, 앱 설치(사이드로딩)는 필요 없습니다.** 웹앱(PWA)을 홈 화면에 추가해서 씁니다.

두 가지 방법이 있습니다.

| | 방법 B (권장): 인터넷에 올리기 | 방법 A: 노트북 서버로 테스트 |
|---|---|---|
| 노트북 필요 | **없음**(GitHub 웹에서 설정, 아이폰만으로 가능) | 켜져 있어야 함 |
| 오프라인 | **됨**(한 번 열어 두면) | 안 됨(http라서 서비스 워커 불가) |
| 시간 | 약 10분(처음 한 번) | 약 5분 |
| 용도 | **평소에 쓰기** | 코드 고치면서 확인 |

---

## 방법 B — GitHub Pages (가장 쉬운 방법)

이 저장소는 **공개(public)** 라서 GitHub Pages가 **무료**입니다. 배포 설정(`.github/workflows/pages.yml`)은 이미 들어 있고, 코드를 올리면 테스트를 돌린 뒤 **자동으로 배포**합니다.

### B-0. GitHub 화면 지도 (처음 보는 분용)

GitHub는 코드를 보관하는 웹사이트이고, 이 프로젝트의 "집"은 아래 주소입니다.

> **https://github.com/7fsikMinQ/Game**

저장소 화면 맨 위에는 탭이 줄지어 있습니다(아이폰 Safari에서는 가로로 스크롤되거나 `…` 메뉴 안에 들어 있을 수 있습니다. 안 보이면 주소창 왼쪽 **aA → 데스크탑 웹 사이트 요청**을 누르세요).

| 탭 | 무엇이 있나 | 이 프로젝트에서 쓰는 때 |
|---|---|---|
| **Code** | 파일 목록. 폴더: `baseball/`(야구) `soccer/`(축구) `docs/`(설명서) `tools/`(도구) `.github/`(자동 배포 설정) | 파일 구경, 설명서 읽기(`docs/…md`를 누르면 화면에 그대로 보임) |
| Issues / Pull requests | 요청·검토 기능 | 쓰지 않아도 됩니다 |
| **Actions** | 자동 작업(테스트 + 배포)의 실행 기록. 초록 ✅ = 성공, 빨강 ❌ = 실패, 노랑 ● = 진행 중 | **배포가 끝났는지 확인** |
| **Settings** | 저장소 설정 | **Pages**(웹사이트로 공개) 켜기. 이미 한 번 해 두셨습니다 |

**브랜치(가지)란?** 같은 저장소 안의 작업 버전입니다. 이 저장소의 기본 브랜치는 `claude/serene-franklin-tpdu4g` 이고, 자동 배포는 이 브랜치에 코드가 올라갈 때마다 실행됩니다. Code 탭 왼쪽 위의 브랜치 이름 버튼에서 확인할 수 있습니다. 헷갈리면 건드리지 마세요.

### B-1. Pages 켜기 (처음 한 번 — 이미 완료했다면 건너뛰기)

1. 저장소 → **Settings → (왼쪽 메뉴) Pages**
2. **Build and deployment → Source** 를 **GitHub Actions** 로 선택(저장은 자동). "Jekyll", "Static HTML" 같은 추천 카드는 **무시**합니다.
3. **Actions** 탭 → 왼쪽 **Deploy to GitHub Pages** → 가장 위 실행을 누르고, 실패(❌)했다면 오른쪽 위 **Re-run all jobs**. 실행 기록이 없다면 **Run workflow → 브랜치 `claude/serene-franklin-tpdu4g` → Run workflow**.
4. **1~3분 뒤 초록 ✅** 가 뜨면 완료. (두 단계: `test` → `deploy`, 둘 다 초록이어야 함)
5. 주소 확인: Settings → Pages 맨 위 **"Your site is live at …"** 또는 아래 주소.
   - 목록: `https://7fsikminq.github.io/Game/`
   - 야구: `https://7fsikminq.github.io/Game/baseball/`
   - 축구: `https://7fsikminq.github.io/Game/soccer/`

> 주소의 `7fsikminq` 는 **소문자**, `Game` 은 **대문자 G** 입니다. 틀리면 404가 뜹니다.

### B-2. 아이폰에서 설치 (게임마다 따로)

1. 아이폰 **Safari**로 위 주소(야구 또는 축구)를 엽니다. (Chrome 등 다른 앱이 아니라 **Safari**)
2. 화면 아래 **공유 버튼(□에 ↑ 화살표)** → 목록을 아래로 내려 **홈 화면에 추가**. (공유 버튼이 안 보이면 주소창 오른쪽 `…`)
3. **웹 앱으로 열기** 스위치가 있으면 **켜고** → 오른쪽 위 **추가**. 홈 화면에 아이콘이 생깁니다.
4. **홈 화면의 아이콘으로 실행**합니다. 첫 실행은 **인터넷이 켜진 상태**에서 열어 두세요(파일을 기기에 저장하는 시간).
5. **오프라인 확인**: 비행기 모드를 켜고 아이콘으로 실행 → 열리면 성공.
6. 두 번째 게임도 같은 방법으로 설치하면 아이콘이 따로 생깁니다. **저장 데이터도 게임마다 따로**입니다.

### 꼭 지킬 것: 설치한 아이콘으로만 플레이하기

- Safari 탭에서 하던 진행 상황은 **설치한 앱으로 이어지지 않는다**는 보고가 있습니다(저장소가 분리됨, 공식 확인은 못 함). 설치 후에는 **아이콘으로만** 플레이하세요.
- 옮기려면: 구단 탭 → 설정 → **백업/복원** → 백업(복사 또는 파일) → 설치한 앱에서 **복원**.
- iOS는 **7일간 쓰지 않은 사이트의 웹 데이터를 지울 수 있습니다**. 홈 화면 앱이 면제인지는 공식 확인이 안 됐습니다. 앱이 영구 저장을 요청하고 **7일마다 백업 알림**을 띄우지만, **가끔 백업 파일을 "파일" 앱(iCloud Drive)에 저장**해 두는 것이 가장 안전합니다.
- 야구는 **v2로 새로 만들어서 예전 야구단(v1) 저장 데이터와 호환되지 않습니다**. 처음부터 시작합니다.

### 업데이트 받기

코드를 올리면 자동 배포됩니다. 앱은 **온라인일 때 열 때마다 최신 파일을 받습니다**(네트워크 우선 + 오프라인 대비 저장). 앱을 **완전히 닫았다가(앱 전환 화면에서 위로 밀어 종료) 다시 열면** 새 버전이 반영됩니다. 그래도 안 바뀌면 앱을 지우고 다시 추가하세요(**먼저 백업**).

## 방법 A — 노트북에서 서버 켜서 테스트 (선택)

### A-0. 준비물 (한 번만, 윈도우 PowerShell)

| 항목 | 설치 | 확인 |
|---|---|---|
| Node.js 20 이상 | `winget install OpenJS.NodeJS.LTS` | `node -v` |
| Git | `winget install Git.Git` | `git --version` |

설치 후 PowerShell을 **새로 열어야** 합니다. Git이 싫으면 GitHub에서 **Code → Download ZIP** 으로 받아도 되고, USB로 폴더를 옮겨도 똑같이 동작합니다(의존성 없음).

### A-1. 받기

```powershell
git clone https://github.com/7fsikMinQ/Game.git
cd Game
git checkout claude/serene-franklin-tpdu4g
```

### A-2. 테스트 → 서버

```powershell
npm test        # 마지막에 fail 0 이면 정상 (또는 test.bat 더블클릭)
npm start       # 서버 실행 (또는 start.bat 더블클릭)
```

출력 예: `아이폰(같은 Wi-Fi)  http://192.168.0.23:8080/soccer/`

- Windows 방화벽 경고가 뜨면 **"개인 네트워크 허용"**.
- 아이폰을 **노트북과 같은 Wi-Fi**에 연결하고 Safari로 그 주소를 엽니다.
- 안 열릴 때: 같은 Wi-Fi인지, 방화벽 허용했는지, 주소 끝에 `/soccer/`(또는 `/baseball/`)를 썼는지, 카페·학교 Wi-Fi는 기기 간 통신을 막는지 확인. 포트 충돌은 `$env:PORT=8081; npm start`.

### A-3. 한계

주소가 `http://`라서 **오프라인 캐시가 안 되고**, 노트북 서버가 꺼지면 앱이 열리지 않습니다. 저장 데이터는 이 주소에 묶여 **방법 B 주소로 옮기면 새로 시작**됩니다(백업/복원으로 옮기기).

## 점검표 (아이폰 실기기)

이 환경에서는 Chromium(아이폰 크기)까지만 검증했습니다. 아이폰에서 직접 확인해 주세요. 빠르게 보려면 **개발자 메뉴**(상단 제목을 3초 안에 7번 탭)의 시간 배속 x60/x900을 쓰세요.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| Pages 설정이 안 보임 / Actions가 실패 | Settings → Pages 에서 Source가 **GitHub Actions** 인지. 저장소가 공개인지(공개 아님이면 유료 플랜 필요) |
| `Get Pages site failed` | Pages를 켜기 전에 돌았음 → B-1의 2번 후 Actions에서 **Re-run all jobs** |
| 아이폰 주소가 404 | 주소 끝의 `/Game/baseball/`, `/Game/soccer/` 대소문자(저장소 이름 `Game`), 배포가 끝났는지 Actions의 초록 ✅ 확인 |
| 앱이 예전 화면 | 앱을 완전히 닫았다 열기. 안 되면 지우고 다시 추가(**백업 먼저**) |
| 진행 상황이 사라짐 | 주소가 바뀌었거나(A→B, 도메인 변경), Safari 탭과 설치 앱의 저장소가 다름, iOS의 웹 데이터 삭제 → **백업/복원** |
| 시간이 안 흐르는 것 같음 | 카운트다운은 앱이 열려 있을 때만 움직입니다. 닫아둔 동안의 경기는 다시 열 때 반영됩니다 |
| 열 때 몇 초 멈춤 | 오래 비웠다 열면 최대 120라운드를 계산합니다("계산 중" 화면) |
| 오프시즌에서 멈춤 | 방치형 자동 진행이 꺼져 있음(설정에서 켜기) |
| `npm`이 인식 안 됨 | Node.js 설치 후 PowerShell을 새로 열기. 안 되면 `node tools/serve.mjs` |
| `npm test` 실패 | 출력의 `✖` 줄을 그대로 알려주세요 |
